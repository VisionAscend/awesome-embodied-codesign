# 具身智能软硬件协同设计 · 精选阅读

**少而精：12 篇能改变设计决策的论文。** 共同回答一个问题：模型和任务固定时，改动机器人的身体、传感器、示教装置或执行接口，真机表现会怎样变化？

收录标准：① 有明确的硬件或接口改动；② 有对照、消融或真机实测；③ 结论能落成一条具体的选型规则。经典与近期各半，不追求覆盖面。

> 读法：先扫总览表，再读与当前决策相关的一组。每篇末尾的「设计启示」可以直接拿去评审。

## 一、身体与形态：让优化器选硬件

<a id="hwas"></a>
### 1. Hardware as Policy · 2020

**改了什么** — 把腱驱动手的滑轮半径、弹簧刚度、预紧角等可制造参数，与 RL 策略联合优化，再按搜索结果造出手。

**证据** — 优化出的手在真机上完成指尖捏取和包络抓取；仿真里的参数搜索能直接转成实物。

**设计启示** — 手部机构不该"先定硬件再调策略"。把可制造参数放进优化循环，才能得到适配任务的抓形。
[论文](https://arxiv.org/abs/2008.04460) · [项目页](https://roamlab.github.io/hwasp/)

<a id="robogrammar"></a>
### 2. RoboGrammar · 2020

**改了什么** — 用图文法生成合法机器人结构，RL 按地形评价，自动搜索腿式机器人的身体方案。

**证据** — 针对不同地形生成了结构差异明显、优于手工基线的设计（仿真验证）。

**设计启示** — 结构搜索的价值在于给出针对任务分布的**候选集**；落地前仍要制造和实测，不要把它当作单一最优解。
[论文](https://doi.org/10.1145/3414685.3417838)

<a id="unimal"></a>
### 3. Embodied Intelligence via Learning and Evolution · 2021

**改了什么** — 让虚拟生物的形态与控制策略共同进化（"unimal" 设计空间），再比较不同身体的学习与迁移能力。

**证据** — 共同进化得到的身体在新任务上迁移更好；形态本身会影响策略学习的速度和效果。

**设计启示** — 身体参数应作为"提升可学习性"的变量来选，而不是固定身体之后才调策略。
[论文](https://www.nature.com/articles/s41467-021-25874-z)

<a id="leap"></a>
### 4. LEAP Hand · 2023

**改了什么** — 16 自由度拟人手，3D 打印、总价约 2000 美元、装配简单，全部开源。

**证据** — 该手在真机上支撑了 RL 掌内操作等大量后续工作，成为事实上的通用实验平台。

**设计启示** — 可复现性是硬件论文的一等公民：低成本开源手让"换手做对照"变得可行，这比单点性能更重要。
[论文](https://arxiv.org/abs/2309.06440) · [项目页](https://leaphand.com)

## 二、传感与执行器接口

<a id="gelsight"></a>
### 5. GelSight · 2017

**改了什么** — 弹性体加相机的高分辨率触觉传感器，从接触面图像反推几何与力。

**证据** — 能估计微米级表面几何与接触力，成为后续触觉操作研究的通用感知接口。

**设计启示** — 触觉设计的目标是"给策略提供任务所需的接触可观测性"；先问需要多高的分辨率，再选传感器。
[论文](https://doi.org/10.3390/s17122762)

<a id="anyskin"></a>
### 6. AnySkin · 2024

**改了什么** — 把磁性软皮与电子读出解耦，皮肤磨损后可现场更换，不必重新标定整只传感器。

**证据** — 冻结策略、直接换一块同型皮肤后，任务成功率仅有小幅下降，远高于纯视觉基线。

**设计启示** — 触觉硬件要按耗材设计：更换成本、换件后的信号一致性，应当写进验收标准。
[论文](https://arxiv.org/abs/2409.08276)

<a id="factr"></a>
### 7. FACTR · 2025

**改了什么** — 遥操作端把从臂受力反馈给操作者；训练端用课程学习引导策略利用力信号。

**证据** — 在接触丰富的任务上，力反馈加课程训练明显优于纯视觉策略。

**设计启示** — 传感器装上不等于策略会用。传力硬件和训练方法要一起设计、一起验证。
[论文](https://arxiv.org/abs/2502.17432)

## 三、示教与数据采集硬件

<a id="aloha"></a>
### 8. ALOHA / ACT · 2023

**改了什么** — 低成本主从臂遥操作系统，关节空间直接映射，人手带着从臂完成示教。

**证据** — 每个任务约 50 条示教即可学会双手精细操作（开调味杯、装电池等），并自主执行。

**设计启示** — 示教接口越接近最终执行方式，学到的策略越容易复现；采集硬件的保真度决定了数据分布。
[论文](https://arxiv.org/abs/2304.13705) · [项目页](https://tonyzhaozh.github.io/aloha/)

<a id="umi"></a>
### 9. UMI · 2024

**改了什么** — 手持夹爪加鱼眼相机的采集装置，记录人类在真实环境中的操作，再重定向到不同机械臂。

**证据** — 同一策略在 UR5e 与 Franka 上执行；去掉感知与动作的时延匹配后，动作出现明显抖动。

**设计启示** — 跨本体部署要同时满足两个接口条件：几何一致、时间一致。只对齐动作空间不够。
[论文](https://arxiv.org/abs/2402.10329) · [项目页](https://umi-gripper.github.io/)

<a id="dexcap"></a>
### 10. DexCap · 2024

**改了什么** — 便携式手部动作捕捉系统（腕部相机加 SLAM），在自然环境中采集灵巧操作数据。

**证据** — 采集数据训练的策略可在真机执行，并可重定向到不同构型的手和人形机器人。

**设计启示** — 采集硬件的形态决定了能采到什么样的行为；想要灵巧操作，就需要能记录手指级动作的装置。
[论文](https://arxiv.org/abs/2403.07788)

## 四、部署：身体和时间变了，控制怎样跟上

<a id="selfmodel"></a>
### 11. 任务无关的自建模机器 · 2019

**改了什么** — 不给运动学、动力学先验，让机器人用自己的电机指令和视觉自学身体模型。

**证据** — 学到的模型足以在真机上规划抓取和放置；部件损坏或被替换后，模型能在短时间内修正，任务恢复。

**设计启示** — 换件、损伤、标定漂移都应触发"在线重估身体"，而不是重训整个策略。自建模能力本身是种可部署性设计。
[论文](https://www.science.org/doi/10.1126/scirobotics.aau9356)

<a id="rtc"></a>
### 12. Real-Time Chunking · 2025

**改了什么** — 在执行当前动作块的同时预测下一块，并约束"已承诺执行"的前缀，让策略适配推理延迟。

**证据** — 注入 100 毫秒和 200 毫秒额外延迟后，吞吐量仍优于基线；基线在延迟下出现停顿和振荡，甚至触发保护停机。

**设计启示** — 推理延迟是接口参数，不是实现细节。策略、推理栈和执行频率必须放在一起设计。
[论文](https://arxiv.org/abs/2506.07339)

## 选文标准与未收录

- **在精不在多。** 只收能落成设计规则的论文；同一结论不重复收录，宁缺毋滥。
- **要证据。** 纯算法改进、纯硬件展示（无对照或无任务表现）不收；仿真-only 的工作只在提出新设计空间时收录（如 RoboGrammar、unimal）。
- **时间范围。** 经典工作保留 2017 年以来的少数奠基论文，其余以 2023–2025 年为主。
- **口径。** 成功率、速度、能耗均按原论文任务定义；年份按首次公开版本标记。
